# Experimental VISIT DBF current-patient observation

Status: superseded by ADR 0006

The existing queue remains governed by `RG011M1.DBF`, and the current-patient observation is introduced as an optional, read-only experiment over `RG011M1_VISIT.DBF`. The experiment reports candidates and uncertainty in a separate per-room `看診中列表（實驗）` above each waiting list, never changes queue membership, order, presence, or HIS data, and in this PoC never emits `ACTIVE`; controlled observations must validate an inference rule before that state is considered in a future change. Before validation, the list shows non-`NONE` evidence states with explicit state badges; `NONE` has no patient row, and read errors appear as an error banner rather than as a patient. The list follows the browser's selected `TIME_KIND`; candidates whose physician does not map to either room appear only in a separate read-only unmatched diagnostic area. At startup it treats the current VISIT file as a baseline, so existing rows are not replayed as new events; a restart rebuilds that baseline because raw observation state is not persisted. A new or changed physical record is accepted only after two consecutive successful reads produce the same complete bytes, preventing partial HIS writes from becoming events. It preserves physical DBF record numbers, prefers exact `SYS_2015` linkage, falls back only to a unique composite identity, and never uses `NUM` alone. It coalesces repeated rows for the same encounter into one candidate while retaining their evidence locators, treats multiple conflicting candidates as ambiguous, and excludes VISIT records associated with an encounter already in the HIS-derived `完成` state because opening that completed encounter can create a non-clinical VISIT record. This exclusion is scoped to the same encounter／掛號; a later encounter with the same `NUM` remains eligible. Only current-date, recognized-session VISIT records with a unique encounter association can enter a room candidate list; other observations remain diagnostic but unresolved. If a valid candidate record becomes logically deleted while its encounter is not completed, only that evidence is removed; the candidate disappears when no other valid evidence remains, and deletion alone does not mean `完成`. If a read or file-layout failure occurs, the monitor fails closed, reports an error or stale observation, and does not invent `NONE` or a new candidate. It does not persist raw VISIT or patient snapshots. This proposal supplements rather than supersedes ADR 0002; acceptance requires repeatable controlled comparisons with the original HIS waiting-room display.
